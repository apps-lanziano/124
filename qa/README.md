# 🛡️ סוכני הבדיקה — אפליקציית טייסת 124

מערכת שרצה מדי יום, בודקת את האפליקציה מקצה לקצה, ומגישה דוח אחד בעברית.
נועדה להחליף את הבדיקה הידנית — הכניסה לכל יוזר בנפרד והמעבר על כל מסך.

## הרצה

```bash
node qa/run_daily.mjs
```

הדוח נשמר ב-`qa/reports/YYYY-MM-DD.md` וגם ב-`qa/reports/latest.md`, ומודפס למסך.
קוד יציאה `1` אם נמצא ממצא חמור, אחרת `0`. זמן ריצה: ~90 שניות.

אפשר להריץ כל סוכן בנפרד:

```bash
node qa/scan_roles.mjs      # זהויות ומסכים
node qa/scan_security.mjs   # אבטחה
node qa/scan_quality.mjs    # שיפור וייעול
```

## הסוכנים

### 1. סריקת זהויות ומסכים — `scan_roles.mjs`

נכנס בתור **כל זהות באפליקציה** דרך מסלול ההתחברות האמיתי (כולל שער ה-PIN),
ועובר על **כל מסך שגלוי לאותה זהות**:

- 8 מסגרות × (מפקד + חייל) = 16 זהויות
- מנהל מערכת, קצין טכני, אחראי תקציבים = 3 זהויות
- סה"כ ~19 זהויות, ~99 מסכים

מדווח על: כשל התחברות, מסך שלא נטען, מסך שנתקע על "טוען…", ומסך ריק,
וכן **כל שגיאת JavaScript** שנזרקה — כולל כאלה שלא נראות למשתמש אבל
מתבטאות בנתונים חסרים או בכפתור שלא מגיב.

### 2. בדיקות רגרסיה — `qa/suite/`

20 קבצי בדיקה שנצברו מתיקוני באגים אמיתיים. כל אחד מהם נכתב אחרי באג
שקרה בפועל, כדי שהוא לא יחזור. מכסים בין השאר:

- יושרת שמירה (כשל לא מוצג כהצלחה)
- פרסום כלל-טייסתי מול מקומי
- הרשאות נע"ת
- מרוץ כתיבה על רשימת הצוות (הבאג שמחק PIN-ים)
- נתיבי ההתראות
- יומן פעולות

### 3. אבטחת מידע — `scan_security.mjs`

- **בדיקת XSS חיה** (`lib/xss_probe.mjs`) — מזריק מטענים עוינים ל-11 סוגי
  שדות שמשתמשים מקלידים, מריץ את האפליקציה, ובודק אם המטען **באמת רץ**.
  לא ניחוש סטטי — ממצא כאן הוא פרצה מוכחת.
- כללי Firestore: הרשאות פתוחות, חובת אימות, שאילתות list, הפרדת מסגרות
- סודות בקוד, סינקים שמריצים קוד מחרוזתי
- חוזק שמירת ה-PIN
- קוד חיצוני מ-CDN בלי בדיקת שלמות (SRI)
- מידע רגיש ב-localStorage

### 4. שיפור וייעול — `scan_quality.mjs`

- **שמירה על תיקונים קריטיים** — ייכשל אם מישהו יחזיר בעתיד את התבנית
  שמחקה PIN-ים או את זו שהעלימה קרא-וחתום
- קריאות אחסון סדרתיות בלולאה (ביצועים)
- קוד מת, פונקציות ארוכות מדי, גודל הקובץ
- נגישות, סימוני TODO

## ⚠️ ניטור חי — מה המערכת הזו *לא* עושה

הסוכנים רצים על **הקוד**, לא על השרת החי. הם לא רואים תעבורה אמיתית,
ולכן **אינם מזהים חדירה בזמן אמת**.

זיהוי חדירה אמיתי חייב לרוץ בצד Firebase, ומופעל בקונסולה — לא מהקוד:

| מה | איפה מפעילים | מה זה נותן |
|---|---|---|
| **App Check enforcement** | Firebase Console → App Check → Firestore → Enforce | חוסם כל גישה שלא מגיעה מהאתר האמיתי. **ההגנה החשובה ביותר.** |
| **התראות תקציב** | Google Cloud → Billing → Budgets & alerts | מייל על קפיצה חריגה בשימוש — לרוב הסימן הראשון לשאיבת נתונים |
| **Firebase Auth logs** | Firebase Console → Authentication → Users | ניסיונות התחברות כושלים חוזרים |
| **Cloud Audit Logs** | Google Cloud → Logging → `datastore.googleapis.com` | תיעוד כל קריאה/כתיבה למסד, כולל מקור |
| **התראה על חריגה** | Cloud Logging → Create alert על נפח קריאות חריג | מייל/SMS בזמן אמת |

בתוך האפליקציה עצמה כבר קיימים שני יומנים שמשמשים לתחקור אחרי אירוע:
**📜 יומן** (פעולות פרסום ומחיקה) ו-**✍️ חתימות** (היסטוריית חתימות).

קובץ `.mjs` חדש ב-`qa/suite/` שמסתיים ב:

הוא ייאסף אוטומטית לריצה היומית. קוד יציאה שאינו 0 = כשל שיופיע בדוח.

## חיבור לנתונים החיים של Firebase

בלי החיבור הזה הסוכנים בודקים רק את **הקוד**. איתו הם בודקים גם את
**הנתונים האמיתיים** של הטייסת ותופסים דברים שאי אפשר לראות בקוד:

- קרא-וחתום שפורסם אבל לא הגיע לכל המסגרות (התקלה שרדפה אותנו)
- מסגרת שלא מקבלת התראות כלל — אין בה אף מכשיר רשום
- כמה אנשים עדיין בלי PIN
- לוח צוות שלא עודכן שבועות
- רשומות צוות כפולות או שבורות

### פרטיות — חשוב לקרוא לפני

**המאגר הזה ציבורי.** לכן:

1. הסוכן **לעולם לא מוציא שמות של אנשים** — רק מספרים ושמות מסגרות.
2. ממצאי הנתונים החיים **לא נשמרים במאגר**. הם נכתבים ל-
   `qa/reports/latest_personal.md` שמוחרג מגיט, וה-workflow מוחק אותו
   לפני השמירה — הגנה כפולה, כי טעות אחת בקובץ ההחרגה = פרסום נתונים.
3. הדוח שכן נשמר במאגר מכיל רק את בדיקות הקוד.

### הפעלה — פעם אחת

**שלב 1: יצירת מפתח קריאה בלבד**

1. היכנס ל-[Google Cloud Console → IAM](https://console.cloud.google.com/iam-admin/serviceaccounts)
   ובחר את הפרויקט `squadron124-96357`
2. **Create Service Account**
   - שם: `qa-readonly`
   - תיאור: `בדיקה יומית — קריאה בלבד`
3. בשלב ההרשאות בחר תפקיד **`Cloud Datastore Viewer`** בלבד
   ⚠️ אל תיתן `Owner` או `Editor` — התפקיד הזה מאפשר קריאה ותו לא,
   כך שגם אם המפתח ידלוף אי אפשר למחוק או לשנות שום דבר
4. סיים, לחץ על החשבון שנוצר → לשונית **Keys** → **Add Key** →
   **Create new key** → **JSON** → הקובץ יורד למחשב

**שלב 2: הכנסת המפתח ל-GitHub**

1. [Settings → Secrets and variables → Actions](https://github.com/eladlanzianog-sys/124/settings/secrets/actions)
2. **New repository secret**
   - Name: `FIREBASE_SA_KEY`
   - Secret: הדבק את **כל תוכן קובץ ה-JSON** שהורדת
3. Add secret

זהו. הבדיקה הבאה כבר תכלול את הנתונים החיים.

> אל תשלח את הקובץ הזה בצ'אט, במייל או בוואטסאפ. GitHub Secrets מוצפן
> ולא מוצג בלוגים — זה המקום הנכון היחיד.

### ביטול

מחיקת ה-Secret מ-GitHub, או מחיקת החשבון מ-Google Cloud. הסוכנים
ימשיכו לרוץ על הקוד כרגיל וידלגו על הנתונים החיים.
