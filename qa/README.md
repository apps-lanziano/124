# 🛡️ סוכני הבדיקה — אפליקציית טייסת 124

מערכת שרצה מדי יום, בודקת את האפליקציה מקצה לקצה, ומגישה דוח אחד בעברית.
נועדה להחליף את הבדיקה הידנית — הכניסה לכל יוזר בנפרד והמעבר על כל מסך.

## הרצה

```bash
node qa/run_daily.mjs
```

הדוח נשמר ב-`qa/reports/YYYY-MM-DD.md` וגם ב-`qa/reports/latest.md`, ומודפס למסך.
קוד יציאה `1` אם נמצא ממצא חמור, אחרת `0`. זמן ריצה: ~90 שניות.

אפשר להריץ כל סוכן בנפרד (ר' מיקומים בטבלה למטה):

```bash
node qa/agents/functional/identity_screens.mjs
node qa/agents/security/static_audit.mjs
node qa/agents/quality/code_health.mjs
```

## מבנה ארגוני — 3 שכבות

```
qa/registry.mjs        ← מרשם: איזה סוכנים קיימים ובאיזה סדר (מקור אמת יחיד)
qa/orchestrator.mjs     ← המטה: טוען סוכן, מריץ, אוסף ממצאים, מבודד כשלים
qa/report.mjs           ← בניית הדוח: הפרדת פרטיות + שפה פשוטה + מגמות
qa/run_daily.mjs        ← נקודת הכניסה: מחבר את שלושת אלה + כותב קבצים
```

כל סוכן הוא מודול ב-`qa/agents/<אגף>/<שם>.mjs` שמייצא אובייקט אחיד:

```js
export default {
  id: 'security/static-audit',   // מזהה יציב — המפתח למגמות ולתרגום כותרות
  name: 'ביקורת אבטחה סטטית',     // שם עברי לתצוגה
  kind: 'static' | 'dynamic' | 'live' | 'human',   // איך בודק
  domain: 'functional' | 'security' | 'quality' | 'data' | 'product',  // מה שואל
  privacy: 'public' | 'personal',   // ← קובע לבד אם הפלט נכנס לדוח הציבורי!
  async run(){ return { summary, findings }; }
};
```

**הוספת סוכן חדש:** צור קובץ `.mjs` באגף המתאים תחת `qa/agents/`, ייצא אובייקט
בצורה הזו, והוסף שורת `import` אחת ל-`qa/registry.mjs`. זהו — הוא ייכנס
אוטומטית להרצה היומית, לדוח, ולמעקב המגמות (אם `privacy:"public"`).

### למה `privacy` הוא שדה מוצהר ולא ניחוש

`report.mjs` מפריד בין הדוח הציבורי (נשמר במאגר, נשלח במייל) לדוח האישי
(מכיל נתוני טייסת אמיתיים) **לפי `section.privacy`** — לא לפי שם הסוכן.
כך שינוי עתידי בשם סוכן לא יכול בטעות לדלוף נתונים למאגר הציבורי.

## מגמות בין ריצות

כל ממצא ציבורי (לא `info`) מקבל חתימה יציבה (`lib/state.mjs`) ומסומן בדוח:

- **🆕 חדש** — לא הופיע אתמול
- **↔ ממשיך X ימים** — אותו ממצא נמשך כבר X ימים

המצב נשמר ב-`qa/reports/state.json` (נכנס למאגר יחד עם `latest.md`, בדיוק
כמו כל שינוי קוד אחר) כדי לשרוד בין הרצות של ה-Action. הקובץ מכיל רק
חתימות וכותרות ממצאי קוד — לעולם לא נתוני "נתונים חיים" (אישי, מוחרג).

## ⚠️ ניטור חי — מה המערכת הזו *לא* עושה

הסוכנים רצים על **הקוד**, לא על השרת החי (מלבד `data/live_firebase`, שרץ
על נתונים אמיתיים אך עדיין לא רואה תעבורה בזמן אמת). לכן **אינם מזהים
חדירה בזמן אמת**.

זיהוי חדירה אמיתי חייב לרוץ בצד Firebase, ומופעל בקונסולה — לא מהקוד:

| מה | איפה מפעילים | מה זה נותן |
|---|---|---|
| **App Check enforcement** | Firebase Console → App Check → Firestore → Enforce | חוסם כל גישה שלא מגיעה מהאתר האמיתי. **ההגנה החשובה ביותר.** |
| **התראות תקציב** | Google Cloud → Billing → Budgets & alerts | מייל על קפיצה חריגה בשימוש — לרוב הסימן הראשון לשאיבת נתונים |
| **Firebase Auth logs** | Firebase Console → Authentication → Users | ניסיונות התחברות כושלים חוזרים |
| **Cloud Audit Logs** | Google Cloud → Logging → `datastore.googleapis.com` | תיעוד כל קריאה/כתיבה למסד, כולל מקור |
| **התראה על חריגה** | Cloud Logging → Create alert על נפח קריאות חריג | מייל/SMS בזמן אמת |

בתוך האפליקציה עצמה כבר קיימים שני יומנים שמשמשים לתחקור אחרי אירוע:
**📜 יומן** (פעולות פרסום ומחיקה) ו-**✍️ חתימות** (היסטוריית חתימות).

## הוספת בדיקת רגרסיה חדשה

קובץ `.mjs` חדש ב-`qa/suite/` שמסתיים ב:

```js
process.exit(allPass ? 0 : 1);
```

הוא ייאסף אוטומטית ע"י `agents/functional/regression_suite.mjs`. קוד
יציאה שאינו 0 = כשל שיופיע בדוח.
